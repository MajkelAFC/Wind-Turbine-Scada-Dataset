# 🌬️ Wind Energy Analytics Platform

A Data Engineering pipeline designed to process wind turbine telemetry data, clean sensor readings, and **calculate the total power generated by wind turbines**.

Built with **Python**, **Apache Airflow**, **PostgreSQL**, and **Docker**, using **Domain-Driven Design (DDD)** and the **Medallion Architecture**.

---

## 🎯 Main Project Goal & Problem
*(Business Analyst perspective)*

### 🎯 Main Goal
The primary objective of this project is to **accurately calculate and analyze the actual power output (energy produced)** of wind turbines from raw sensor telemetry.

### ⚠️ The Problem
Sensors on wind turbines send massive amounts of data, but raw feeds are often noisy and broken:
* **Invalid Power Readings:** Sensors sometimes record impossible negative power output numbers.
* **Corrupted Timestamps:** Latency causes missing or malformed time logs.
* **Duplicate Telemetry:** Network retries send the exact same readings multiple times.

If you calculate total power production using raw data, your financial and energy reports will be wrong. This platform provides an automated pipeline that cleans telemetry before calculating power metrics.

---

## 🏢 Business Context
*(Business Analyst perspective)*

Why is accurate power output calculation critical for wind farm operations?

* **Evaluating Turbine Performance:** Comparing actual power output against expected generation helps engineers identify underperforming or failing turbines early.
* **Planning Maintenance:** Dropping power generation signals mechanical issues. Catching this early prevents expensive equipment breakdowns.
* **Commercial Reporting:** Energy companies need precise, audit-ready daily metrics on total kilowatt-hours produced for grid operators and clients.

Bad data leads to incorrect energy estimates and lost revenue. Clean power calculations keep the wind farm efficient and profitable.

## 🧠 Proposed Solution & Architecture
*(Architect perspective)*

The project processes power data through 3 distinct layers (**Medallion Architecture**):

| Layer | Stage | What happens here |
| :--- | :--- | :--- |
| 🥉 **Bronze** | Raw Ingestion | Stores raw CSV telemetry logs directly in PostgreSQL without modifications. |
| 🥈 **Silver** | Data Cleansing | Validates records using Python logic. Rejects negative power outputs, fixes bad dates, and removes duplicates. |
| 🥇 **Gold** | Power Analytics | Calculates key metrics, such as average power output per turbine over time, for business reporting. |

### Domain-Driven Design (DDD)

We isolate the core business rules from technical database code:

* `src/domain/` — Contains core validation rules (`wind_turbine.py`). It defines what counts as a valid power reading (e.g., $power \ge 0$). It does not depend on database libraries or Airflow.
* `src/infrastructure/` — Handles technical plumbing like loading CSV files and executing SQL queries in PostgreSQL.

This separation lets you unit-test the power validation logic instantly without running databases or Docker.

## 🔍 Decisions & Rationale
*(Architect + Data Analyst perspective)*

| Decision | Why we chose it |
| :--- | :--- |
| **Domain Model Validation** | Checking power readings in Python models makes domain rules easy to test and update. |
| **3 Data Layers (Medallion)** | Keeps raw sensor history safe in Bronze while serving clean power metrics from Gold. |
| **Apache Airflow** | Automatically orchestrates daily power aggregation and retries failed tasks. |
| **Docker Compose** | Spawns the complete environment (Postgres + Airflow) with a single command. |

🚀 How to Run

1. Start the Environment

Run Docker Compose to start PostgreSQL and Apache Airflow:
Bash

docker compose up -d

2. Access Apache Airflow

Open your web browser and navigate to:

    URL: http://localhost:8080

    Username: admin

    Password: Retrieve the auto-generated password by running:

Bash
docker compose exec airflow cat /opt/airflow/standalone_admin_password.txt

3. Run the Pipeline

    Open Airflow at http://localhost:8080.

    Locate the wind_energy_medallion_pipeline DAG.

    Toggle the switch to Active and click Trigger DAG.
